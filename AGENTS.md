# Правила проекта

Репозиторий содержит лабораторные работы, каждая в своей папке: `lab1/`, `lab2/`, `lab3/` и т. д. Правила ниже общие для всех лаб. В папке лабы лежат её собственные `AGENTS.md` (уточнения), `PLAN.md` (план шагов), `README.md` и исходное ТЗ в `docs/`.

## Архитектура

- Все проекты должны целиться в .NET 10 (`net10.0`, для десктопного UI — `net10.0-windows`).
- Соблюдай SOLID: у каждого типа одна ответственность; расширяй поведение без изменения проверенного кода; подставляемые реализации должны сохранять контракты; разделяй интерфейсы по ролям; зависимости направляй к абстракциям.
- Ввод/вывод пользовательского интерфейса, работа с файлами (Excel, Word), генерация случайных чисел и получение текущего времени должны быть скрыты за интерфейсами.
- Регистрируй зависимости вручную в точке входа приложения (composition root), без DI-контейнера.
- Ядро приложения не зависит от типа пользовательского интерфейса и от формата хранилища.
- Лабы независимы друг от друга: у каждой своё решение (`.sln`) и свои проекты, ссылки между лабами не допускаются.

## Файловые хранилища

- Для Excel используй `ClosedXML`.
- Сохраняй файл после каждой добавленной записи.
- При дозаписи добавляй данные после существующих строк и не изменяй их.
- Если файл заблокирован и запись невозможна, преобразуй ошибку в доменное исключение с понятным сообщением пользователю.

## Тестирование

- Используй xUnit и NSubstitute.
- Unit-тестами покрывай доменную логику и каждое хранилище.
- UI-тестами проверяй сценарии и критерии приёмки из ТЗ лабы.
- E2E-тестами запускай реальное приложение и проверяй его результат и содержимое выходных файлов.

## Git и секреты

- Основная ветка проекта — `main`.
- `.gitignore` должен исключать `bin/`, `obj/` и выходные файлы приложений.
- Используй Conventional Commits: один запрошенный шаг — один коммит; после каждого коммита выполняй `git push`.
- Никогда не используй `git push --force`.
- Не запрашивай токены и пароли и не записывай их в файлы, вывод команд или историю репозитория.
- Не меняй git config и настройки remote без отдельного прямого запроса пользователя.

## Порядок работы

- Выполняй только тот шаг, который запросил пользователь. Не начинай следующие шаги из `PLAN.md` лабы без отдельного запроса.
- После каждого выполненного шага запускай `dotnet test` для решения этой лабы.
- После шага кратко, в 3–5 строках, объясняй, какой принцип SOLID применён и почему, затем останавливайся.
- В новой сессии сначала прочитай этот файл, `git log`, а также `AGENTS.md` и `PLAN.md` текущей лабы.
