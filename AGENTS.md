# Правила проекта

## Архитектура

- Все проекты решения должны целиться в .NET 10 (`net10.0`).
- Соблюдай SOLID: у каждого типа одна ответственность; расширяй поведение без изменения проверенного кода; подставляемые реализации должны сохранять контракты; разделяй интерфейсы по ролям; зависимости направляй к абстракциям.
- Консольный ввод/вывод, работа с Excel, генерация случайных чисел и получение текущего времени должны быть скрыты за интерфейсами.
- Регистрируй зависимости вручную в `Program.cs`, без DI-контейнера.
- Ядро приложения не зависит от консольного или другого типа пользовательского интерфейса.

## Excel-хранилище

- Используй `ClosedXML` для файла `journal.xlsx`.
- Сохраняй файл после каждой добавленной записи.
- При дозаписи добавляй данные после существующих строк и не изменяй их.
- Если файл заблокирован и запись невозможна, преобразуй ошибку в доменное исключение с понятным сообщением пользователю.

## Тестирование

- Используй xUnit и NSubstitute.
- Unit-тестами покрывай валидатор, генератор, сервис и репозиторий.
- UI-тестами на `FakeConsole` проверяй сценарии из раздела «Проверка результата» ТЗ.
- E2E-тестами запускай реальный процесс приложения и проверяй stdout и содержимое `journal.xlsx`. Не отправляй ESC в E2E-ввод.

## Git и секреты

- Основная ветка проекта — `main`.
- `.gitignore` должен исключать `bin/`, `obj/` и `journal.xlsx`.
- Используй Conventional Commits: один запрошенный шаг — один коммит; после каждого коммита выполняй `git push`.
- Никогда не используй `git push --force`.
- Не запрашивай токены и пароли и не записывай их в файлы, вывод команд или историю репозитория.
- Не меняй git config и настройки remote без отдельного прямого запроса пользователя.

## Порядок работы

- Выполняй только тот шаг, который запросил пользователь. Не начинай следующие шаги из `PLAN.md` без отдельного запроса.
- После каждого выполненного шага запускай `dotnet test`.
- После шага кратко, в 3–5 строках, объясняй, какой принцип SOLID применён и почему, затем останавливайся.
- В новой сессии сначала прочитай `AGENTS.md`, `git log` и `PLAN.md`.
- Исходное ТЗ хранится в `docs/`.
