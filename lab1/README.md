# Генератор экзаменационных билетов

Консольное приложение запрашивает фамилию и имя студента, выдаёт случайный номер экзаменационного билета от 1 до 20 и дописывает запись в Excel-файл `journal.xlsx`. Исходное ТЗ лежит в [`docs/`](docs/).

## Требования

- .NET SDK 10.0
- Пакеты NuGet (восстанавливаются автоматически): ClosedXML, xUnit, NSubstitute

## Сборка, запуск и тесты

Команды выполняются из папки `lab1/`.

```bash
dotnet build
dotnet run --project src/TicketGenerator.ConsoleApp
dotnet test
```

Файл `journal.xlsx` создаётся в текущем рабочем каталоге.

Пример сеанса:

```text
Для выхода нажмите ESC.
Last name: Иванов
First name: Иван
Билет № 7
Last name:
```

## Формат журнала

| A         | B          | C            | D                   |
|-----------|------------|--------------|---------------------|
| Last name | First name | Номер билета | Дата и время        |
| Иванов    | Иван       | 7            | 28.10.2026 12:30:00 |

- Если файла нет, он создаётся с шапкой.
- Новые записи добавляются после последней заполненной строки; существующие строки не изменяются.
- Файл сохраняется сразу после каждого студента. Книга сначала записывается во временный файл, который затем заменяет журнал, поэтому аварийное завершение во время сохранения не повреждает ранее введённые данные.

## Структура решения

| Проект | Назначение |
|---|---|
| `TicketGenerator.Core` | Модель `TicketRecord`, интерфейсы `ITicketRepository`, `IRandomNumberSource`, `IClock`, валидатор, генератор номера, сервис выдачи билета и доменное исключение `JournalUnavailableException`. Не зависит от консоли и Excel. |
| `TicketGenerator.Infrastructure` | `ExcelTicketRepository` на ClosedXML, `SystemClock`, `SystemRandomNumberSource`. |
| `TicketGenerator.ConsoleApp` | `IConsole`/`SystemConsole`, посимвольный ввод `ConsoleLineReader`, сценарий `TicketConsoleApplication` и ручная сборка зависимостей в `Program.cs`. |
| `tests/TicketGenerator.UnitTests` | Unit-тесты валидатора, генератора, сервиса и репозитория. |
| `tests/TicketGenerator.UiTests` | Сценарии из раздела «Проверка результата» ТЗ на `FakeConsole`. |
| `tests/TicketGenerator.E2ETests` | Запуск реального процесса с проверкой stdout и `journal.xlsx`. |

## Принятые решения

**Ввод и ESC.** `Console.ReadLine()` не позволяет перехватить ESC, поэтому строка собирается посимвольно через `Console.ReadKey`: Enter завершает ввод, Backspace удаляет последний символ, ESC в любой момент ожидания ввода завершает приложение. Если стандартный ввод перенаправлен (например, в E2E-тестах), клавиши строятся из символов потока, а конец потока считается нажатием ESC.

**Проверка ввода.** Пробелы по краям обрезаются. Пустая строка или строка только из пробелов не принимается: выводится «Значение не может быть пустым. Повторите ввод.», и запрос повторяется.

**Заблокированный файл.** Если `journal.xlsx` открыт в Excel, ошибки ввода-вывода репозитория преобразуются в `JournalUnavailableException`. Приложение не падает: оно выводит сообщение с просьбой закрыть файл и ждёт Enter, чтобы повторить сохранение того же студента (ESC — выход). Введённые данные при этом не теряются.

**Зависимости.** Консоль, Excel, генератор случайных чисел и текущее время скрыты за интерфейсами и подключаются вручную в `Program.cs`, без DI-контейнера. Поэтому тесты подменяют их через NSubstitute или `FakeConsole`.
