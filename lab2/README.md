# Генератор экзаменационных билетов с UI

Десктопное WPF-приложение: экзаменатор выбирает группу и студента из `students.xlsx`, приложение назначает билет из `tickets.docx`, показывает номер и три вопроса в отдельном окне и дописывает строку в журнал `results.xlsx`. Повторно выбранный студент получает тот же билет. Исходное ТЗ лежит в [`docs/`](docs/), английская версия для ассистента — [`docs/SPEC.en.md`](docs/SPEC.en.md).

## Требования

- Windows, .NET SDK 10.0
- Пакеты NuGet (восстанавливаются автоматически): ClosedXML, DocumentFormat.OpenXml, xUnit, NSubstitute, FlaUI

## Сборка, запуск и тесты

Команды выполняются из папки `lab2/`.

```bash
dotnet build
dotnet run --project src/ExamTickets.Wpf -- --data samples
dotnet test
```

Файлы `students.xlsx`, `tickets.docx` и `results.xlsx` ищутся в текущем каталоге; аргумент `--data <папка>` задаёт другой каталог. Рядом с ними пишется лог ошибок `exam-tickets.log`.

E2E-тесты открывают настоящие окна и нажимают клавиши, поэтому `dotnet test` нужно запускать в интерактивном сеансе Windows и не трогать мышь и клавиатуру примерно полминуты.

## Работа с приложением

1. При запуске первый список заполняется группами (имена листов `students.xlsx`).
2. После выбора группы второй список показывает её студентов в формате «Фамилия Имя».
3. Кнопка «Сгенерировать билет» активна, только когда выбраны и группа, и студент.
4. Кнопка открывает окно «Ваш билет № N» с тремя вопросами; строка в `results.xlsx` к этому моменту уже сохранена.
5. Esc закрывает окно результата, главное окно остаётся открытым для следующего студента.

## Форматы файлов

**`students.xlsx`** — один лист на группу, имя листа = имя группы. Строка 1 — заголовок, со строки 2: колонка A — фамилия, колонка B — имя. Лист без студентов — допустимая пустая группа.

**`tickets.docx`** — абзацы вида:

```text
Билет 1
1. Вопрос первый
2. Вопрос второй
3. Вопрос третий
```

Номера вопросов можно набрать текстом или оформить автоматической нумерацией Word. Билет пропускается с записью в лог, если у него меньше трёх вопросов, заголовок не распознан или номер повторяется; если вопросов больше трёх, показываются первые три.

**`results.xlsx`** — создаётся при первом запуске, данные только дописываются в конец:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Группа | Фамилия | Имя | Номер билета | Дата и время | Повтор (да/нет) |
| TI-221 | Иванов | Иван | 4 | 25.11.2026 10:00:00 | нет |
| TI-221 | Иванов | Иван | 4 | 25.11.2026 10:05:00 | да |

## Демонстрационные данные

В [`samples/`](samples/) лежат `students.xlsx` (группы TI-221, TI-222, FAF-231 и «Пустая группа») и `tickets.docx` (билеты 1–5 с набранными номерами, 8–10 с автонумерацией Word и два намеренно некорректных: «Билет 6» с двумя вопросами и «Билет VII»). Файлы пересоздаются командой:

```bash
dotnet run samples/GenerateSamples.cs -- samples
```

## Структура решения

Зависимости направлены внутрь: `Wpf → Presentation → Core ← Infrastructure`.

| Проект | Назначение |
|---|---|
| `ExamTickets.Core` | Модели `Student`, `Ticket`, `ResultRecord`, `TicketAssignment`; интерфейсы `IStudentSource`, `ITicketSource`, `IResultJournal`, `ITicketAssigner`, `IRandomNumberSource`, `IClock`, `IAppLogger`; `TicketParser`, `TicketAssignmentService` и доменные исключения. Не знает о WPF, Excel и Word. |
| `ExamTickets.Infrastructure` | `ExcelStudentSource`, `ExcelResultJournal` (ClosedXML), `DocxTicketSource` (OpenXML), `FileAppLogger`, `SystemClock`, `SystemRandomNumberSource`, `DataPaths` для `--data`. |
| `ExamTickets.Presentation` | `MainViewModel`, `ResultViewModel`, `RelayCommand`, интерфейсы окон `IResultPresenter` и `IUserNotifier`. Целится в `net10.0` и не ссылается на WPF. |
| `ExamTickets.Wpf` | Окна `MainWindow` и `ResultWindow`, `ResultWindowPresenter`, `MessageBoxNotifier` и ручная сборка зависимостей в `App.xaml.cs`. |
| `tests/ExamTickets.UnitTests` | Парсер, чтение Word и Excel, журнал, сервис назначения, лог, пути и демонстрационные файлы. |
| `tests/ExamTickets.UiTests` | ViewModel'и по критериям приёмки ТЗ без открытия окон. |
| `tests/ExamTickets.E2ETests` | FlaUI запускает `ExamTickets.Wpf.exe` во временной папке и проверяет окна и `results.xlsx`. |

## Принятые решения

**Назначение билета.** Студент определяется тройкой «группа + фамилия + имя». Если он уже есть в журнале, берётся номер из самой первой его записи и добавляется строка с «да»; иначе случайно выбирается позиция `1..N` в списке корректных билетов и пишется строка с «нет». Выбор позиции, а не номера, позволяет работать с пропусками в нумерации после отброшенных билетов. Поиск идёт по файлу, поэтому тот же билет выдаётся и после перезапуска приложения.

**Разбор билетов.** Чтение `.docx` (`DocxTicketSource`) отделено от правил разбора (`TicketParser`), поэтому правила тестируются на обычных строках. Автоматическая нумерация Word не хранится в тексте абзаца, и при чтении номер «N. » восстанавливается.

**Ошибки.** Отсутствие `students.xlsx` или `tickets.docx`, отсутствие корректных билетов и повреждённые файлы дают понятное сообщение при запуске, после чего приложение завершается без падения. Если `results.xlsx` открыт в Excel, ошибки ввода-вывода превращаются в `JournalUnavailableException`, и приложение предлагает повторить попытку. Если номер из журнала пропал из `tickets.docx`, показывается сообщение, а новая строка не пишется. Входные файлы читаются с `FileShare.ReadWrite`, поэтому их можно держать открытыми в Excel и Word.

**Сохранение.** Строка пишется сразу после назначения, до показа окна. Книга сначала сохраняется во временный файл, который затем заменяет журнал, поэтому сбой во время записи не повреждает прежние строки.

**Зависимости.** Окна, сообщения, файлы, время и случайные числа скрыты за интерфейсами и собираются вручную в `App.xaml.cs` без DI-контейнера и `StartupUri`. ViewModel'и тестируются с NSubstitute без WPF, а E2E-тесты подменяют только папку данных через `--data`.
